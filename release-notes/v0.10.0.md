## What's new

- **Import from Bitwarden or Vaultwarden by signing in, with no export file.**
  - In the app: **More › Import › Bitwarden or Vaultwarden**. Choose bitwarden.com, bitwarden.eu or your own server, enter your email and master password, and the code from your authenticator app or email if Bitwarden asks.
  - Symbolon downloads your encrypted vault and decrypts it on your device. Nothing is saved unencrypted, and your master password is used once and not kept.
  - What comes across: logins (with one-time-code seeds), cards, identities, notes, SSH keys, custom fields, folders, organization collections, items with their own keys, and passkeys (as Synced passkeys). Items in the trash are left behind.
  - Accounts with weak key derivation (under 100,000 PBKDF2 iterations) are refused, with a way to raise it in Bitwarden. A malicious server could otherwise lower these settings to make your password cheap to guess.
  - Not yet: two-step login by Duo or a security key, and accounts on Bitwarden's newest key format. Use the export file for those.
- **Imported passwords stay secret end to end.**
  - Every imported value, whether from a file or a sign-in, is held as `Secret` bytes from the moment it is read until the vault seals it. That covers passwords, notes, card and identity details, keys and passkeys.
  - Only what Symbolon already lists in plain text is published: item and folder names, site addresses, custom-field labels.
  - Passkey keys are read with Resid's constant-time base64 and secret PKCS#8 reader.
- **One device per security chip.**
  - `device new` no longer replaces another Symbolon device's TPM keys; it refuses and says how to retire that device first.
  - `device forget` removes only keys that belong to its own device.
- **Built with [Resid v0.13.0](https://github.com/larrydewey/Resid/releases/tag/v0.13.0):** AES-CBC, XChaCha20-Poly1305, XAES-256-GCM, PBKDF2 and RSA-OAEP decryption on secret keys, and chunked HTTPS bodies.

## Updating

Install the APK over 0.9.0 or earlier; it is signed with the same key. On Linux, replace the binary with this release's. Symbolon Home updates itself from this release overnight, or run its update script. The browser extension is unchanged apart from its version number.

## Files

- `symbolon-v0.10.0.apk`: the Android app (arm64 and x86_64).
- `symbolon-v0.10.0-linux-x86_64`, `symbolon-v0.10.0-linux-aarch64`: the agent and servers for Linux.
- `symbolon-extension-v0.10.0.zip`: the browser extension.
- `SHA256SUMS`: checksums of the files above.

## Tests

- `symbolon-resid/tests/run.sh` with the agent built against Resid v0.13.0: all 30 unit test files and the services test pass.
- End-to-end suites that pass: cli, home, share, org, store, rotate, fill_lock, browser, ssh, fido, link and protected, plus the new `bitwarden_e2e`.
  - `bitwarden_e2e` runs a Vaultwarden in Docker, filled by an independent Python Bitwarden client, and covers every item type, an organization, Argon2id with an authenticator code, a wrong password and an untrusted certificate.
  - `cli` over TLS and `breach` failed once in the full run under load ("status does not show the pending recovery", "device init"), then passed when run again alone.
  - `tpm` now skips on the build machine, because its TPM holds a real device's keys (the guard this release adds). `fido_usb` was skipped because no key was plugged in.
- Resid v0.13.0 passed all 19 of its suites before release.
- The app: `flutter analyze` finds no issues; `flutter test` passes (127 tests, including the new sign-in tests).
- Sign-in against bitwarden.com itself was not tried; Vaultwarden was. The APK was not tried on a device before release.
