## What's new

- **Protected items.** Mark a vault item protected and opening it needs two parties: this device and your cosigner (on Symbolon Home, the box). A device's own keys no longer open them: whoever has the device and its PIN, or malware on an unlocked device, must also go through the cosigner, which limits and records every opening. It slows and exposes that kind of theft; it doesn't stop it. See [Protected items](https://larrydewey.github.io/symbolon/guide/vault/#protected-items) in the guide and SPEC 18.10.
  - The key behind protected items (the vault OPRF key) is split between your devices, your recovery kit and the cosigner, and is never whole anywhere. It is re-shared when a device is added or removed and carried through recovery. Its public commitments are in the identity log (quorum field 6), so the witnesses see any change to it.
  - The cosigner answers blinded requests: it never learns which item is being opened. It allows each device 60 openings an hour (cosigner policy field 3) and records every opening. During a duress window it refuses openings as if it were offline.
  - **More, Devices, Check protected openings** shows each device's openings for the past hour, day and week. A device opening unusually many items in a day raises a warning on the home screen of every device, shown while the app is unlocked.
  - In the app: the shield on an item's page protects or unprotects it, and protected items carry a shield tag in the list. On the command line: `vault protect`, `vault unprotect`, `device openings` and `device protection enable`.
  - Without the cosigner, protected items still list (name, kind, folder, site) but don't open. Moving one into a shared folder stores it unprotected there, after asking.
- **Not built yet:** protected items without a cosigner (a second device approving each opening), re-keying protected items when the vault key is rotated, and turning protection on for an identity that already has more than one device. SPEC 18.10.8 lists what was built and how it differs from the design.

## Updating

- **Update every device and the cosigner before turning protection on.** Turning it on writes a new field into the identity log. Agents older than 0.9.0 can't read it and stop accepting the log.
- **Symbolon Home:** rebuild the image with this release's agent (`symbolon-home/build.sh` with the Linux binaries below in `symbolon-resid/target/`) and restart it. The cosigner's state from 0.8.x is kept. An older cosigner keeps working for everything else, but can't set up protection or answer openings.
- Install the APK over 0.8.2 or earlier. It is signed with the same key.
- New identities made with 0.9.0 and a 0.9.0 cosigner have protection from the start. An existing identity turns it on with **More, Devices, Turn protected items on** (or `device protection enable`): a re-share with the cosigner, while the identity has one device. Add other devices after that.
- The browser extension is unchanged apart from its version number.

- `symbolon-v0.9.0-linux-x86_64`, `symbolon-v0.9.0-linux-aarch64`: the agent and servers for Linux (and for building Symbolon Home).

## Tests

- `symbolon-resid/tests/run.sh`: all 29 unit test files and the services test pass, among them new tests for dealing and re-sharing the vault OPRF key (with reference vectors from a Python model), quorum field 6 in the log, and the cosigner's opening limits.
- The end-to-end suites pass: cli (plain and TLS), home, share, org, store, rotate, breach, fill_lock, browser, ssh, fido, link and the new protected suite (protect, open, edit, the cosigner stopped, a second device opening the same item, the hourly limit, the openings log, a duress window). `cli` also checks the vault OPRF key survives enrolling and recovery.
- `tpm` failed on the build machine because its TPM was in dictionary-attack lockout from earlier runs, not because of a code change. `fido_usb` was skipped because no key was plugged in.
- The app: `flutter analyze` finds no issues, and `flutter test` passes (125 tests).
- The APK was not tried on a device before release.
