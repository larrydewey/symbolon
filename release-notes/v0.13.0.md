## What's new

- **An SSH certificate authority held by your quorum.** Until now every server had to be given every key: one line per key in `~/.ssh/authorized_keys`, on every server. Now a server can be told once to trust Symbolon's certificate authority, and every key it certifies logs in.
  - `symbolon device ssh ca-new DIR NAME` makes the authority. Like your other keys it is a threshold key: no device holds it whole, and signing a certificate takes the quorum. The agent never offers it for logins and refuses to sign anything with it but certificates.
  - `symbolon device ssh certify DIR KEY CA --principal USER... [--days N]` issues an OpenSSH user certificate for one of your keys (Ed25519, ECDSA or RSA), for the user names given, valid 30 days by default (366 at most). It allows a terminal and port forwarding, nothing else.
  - The agent offers a key's current certificate before the key itself, and never an expired one. The consent window shows when a certificate is used: its authority, its user names and its expiry.
  - When a certificate has less than a third of its life left, it is renewed right after a signature you approve, with the same authority and user names. `symbolon device ssh renew DIR KEY` renews by hand, and `symbolon device ssh refresh DIR` brings in keys, authorities and certificates made on another device.
  - A server trusts the authority per user (`cert-authority,principals="USER"` in that user's `authorized_keys`, which `pylon authorize --ca` writes) or for all users (`TrustedUserCAKeys` in `sshd_config`).
- **The SSH page explains how a server lets you in.** Each key has "Set up a server", which gives its `authorized_keys` line and the `pylon authorize USER@HOST 'LINE'` command for the server you type in. The certificate authority section creates the authority and gives both ways to trust it. Keys show their certificate (authority, user names, expiry) with Issue and Renew, and a Sync button brings in keys made on other devices.
- The consent window sends the signature back as soon as it is made, and stays open only while a renewal finishes.

## Updating

Install the APK over 0.12.1 or earlier; it is signed with the same key. On Linux, replace the binary with this release's. Symbolon Home updates itself overnight. The browser extension is unchanged apart from its version number.

Nothing changes for keys you already use: without a certificate the agent offers the key as before. To use certificates with Pylon, Pylon 0.3.0 or later offers the certificate the agent lists.

## Tests

- The agent and servers are built with Resid v0.14.0 (the APK too: its build now checks out v0.14.0).
- All 30 unit test files and the services test pass.
- End-to-end suites that pass: cli (plain and TLS), home, share, org, store, rotate, breach, fill_lock, browser, ssh, fido, link, protected, bitwarden, lastpass and duress_alert.
- `ssh_e2e` covers the certificate authority against a real OpenSSH server: the authority made by the quorum and refused for anything but certificates; certificates issued for ECDSA, Ed25519 and RSA keys and read by `ssh-keygen -L`; logins with each through `cert-authority` in `authorized_keys` and through `TrustedUserCAKeys`; no login without a certificate or for another user; an expired certificate not offered; renewal, refresh and deletion. Pylon 0.3.0 logged in with the certificate the agent lists.
- The certificate bytes are checked against `ssh-keygen -s` (`sshcert_ref_test`).
- Not tested end to end: the automatic renewal after a signature, which needs a certificate near its expiry (the test has no control of the clock; renewal by hand is tested). Not run: `tpm` (the build machine's TPM holds a real device's keys) and `fido_usb` (no key plugged in).
