## What's new

- **Faster signing.** A signature (a passkey sign-in, or an SSH login through Pylon) is a session with your cosigner through the relay, and the agent used to open a new connection for every request to the relay: each mailbox check every 100 ms, each message read and each message sent, with a full TLS handshake every time. On a phone those handshakes were much of the wait. Now:
  - Requests go out in bursts over one kept HTTPS connection (HTTP/1.1 keep-alive). A connection lasts at most one second, so it never holds up the relay's next worker process, and each request still has 30 seconds to be answered.
  - The check for a new message is the read of that message. Before, the message was fetched once to see that it had arrived and again to read it.
  - After a signature, the agent no longer reads every message of the session a second time to find where its mailbox ends.
  - The cosigner (Symbolon Home) waits for requests the same way: about one new connection a second instead of ten.
- Nothing about what is sent changed: the same envelopes, encrypted and authenticated end to end, the same checks, the same relay protocol. A relay from an earlier version serves the new agent, and the new relay serves earlier agents.

## Updating

Install the APK over 0.12.0 or earlier; it is signed with the same key. On Linux, replace the binary with this release's. Symbolon Home updates itself overnight. The browser extension is unchanged apart from its version number.

## Files

- `symbolon-v0.12.1.apk`: the Android app (arm64 and x86_64).
- `symbolon-v0.12.1-linux-x86_64`, `symbolon-v0.12.1-linux-aarch64`: the agent and servers for Linux.
- `symbolon-extension-v0.12.1.zip`: the browser extension.
- `SHA256SUMS`: checksums of the files above.

## Tests

- With the agent built against Resid v0.13.0, all 29 unit test files and the services test pass.
- End-to-end suites that pass: cli (plain and TLS), home, duress_alert, protected, share, link, ssh, org and store. These cover every multi-party session: key generation, signing, duress signing, enrollment re-share, kit recovery and the Symbolon Home flows.
- The release binaries were tested again on their own: cli (plain and TLS), home, duress_alert, ssh and link pass.
- Signing time in `cli_e2e` over TLS on a laptop's loopback, where a handshake costs little: 2.3 to 3.0 s before, 1.7 to 3.3 s across three runs after. That is within the run-to-run noise. The gain is meant for phones, where the handshakes are slow; it was not measured there.
- Not run for this release: `tpm` (the build machine's TPM holds a real device's keys), `fido_usb` (no key plugged in), and the suites that do not touch the relay session code (rotate, breach, fill_lock, browser, fido, bitwarden, lastpass).
