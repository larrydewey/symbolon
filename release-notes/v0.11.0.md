## What's new

- **Import from LastPass by signing in (experimental).**
  - In the app: **More › Import › LastPass**. Enter your email and master password, then the code from your authenticator app, or approve the sign-in on your phone.
  - What comes across: logins, custom fields, typed secure notes (cards, bank accounts, addresses, Wi-Fi, IDs), and shared folders.
  - LastPass offers no supported way for other apps to sign in, so Symbolon speaks the protocol of LastPass's own command-line tool. If LastPass changes it, this can stop working; the CSV export still works.
  - As with Bitwarden: values stay secret until the vault seals them, and weak key derivation is refused.
- **Import from another app on your phone (Android Credential Exchange).**
  - **More › Import › Another app on this phone.** Android asks which app to take your passwords from: 1Password, Google Password Manager, Bitwarden, Dashlane and others. You confirm in that app, and its passwords and passkeys come across with no export file.
  - Passkeys arrive as Synced passkeys, as from a Bitwarden export.
  - Needs a current Google Play services.
- **Import from 1Password on Linux.**
  - **More › Import › 1Password** reads your items through 1Password's own command-line tool (`op`). The 1Password app asks you to unlock it.
  - The items go straight to Symbolon's agent, never to a file.
- **A wrong two-step code gets another try.** For Bitwarden and LastPass, a wrong, expired or already used code is now shown as such, and you can enter the next one instead of starting over.
- The agent reads these through `device vault signin-lastpass`, and through `device vault import DIR -` with `--format cxf` or `--format 1password-op`.

## Updating

Install the APK over 0.10.0 or earlier; it is signed with the same key. On Linux, replace the binary with this release's. Symbolon Home updates itself overnight. The browser extension is unchanged apart from its version number.

## Files

- `symbolon-v0.11.0.apk`: the Android app (arm64 and x86_64).
- `symbolon-v0.11.0-linux-x86_64`, `symbolon-v0.11.0-linux-aarch64`: the agent and servers for Linux.
- `symbolon-extension-v0.11.0.zip`: the browser extension.
- `SHA256SUMS`: checksums of the files above.

## Tests

- `symbolon-resid/tests/run.sh` with the agent built against Resid v0.13.0: all 30 unit test files and the services test pass.
- End-to-end suites that pass: cli (plain and TLS), home, share, org, store, rotate, breach, fill_lock, browser, ssh, fido, link, protected and bitwarden, plus the new `lastpass_e2e`.
  - `lastpass_e2e` runs against a stand-in for LastPass's servers, built from LastPass's own command-line client. There is no LastPass account to test with, so the real servers were not tried. It covers CBC, ECB and GCM fields, typed secure notes, a shared folder with its RSA-encrypted key, a deleted account left out, an authenticator code, a wrong code first, a push approval, weak key derivation and a wrong password.
  - `cli_e2e` now imports 1Password CLI output and a CXF export (Credential Exchange): logins with one-time-code seeds and custom fields, a passkey, a card, Wi-Fi, an SSH key in a sub-folder, an address.
  - In the full run, `bitwarden_e2e` failed once: its fixture's authenticator code fell within a step of the one used to turn two-step login on, which Vaultwarden refuses. The test was fixed, and the agent now asks again after a wrong code. `bitwarden_e2e`, `lastpass_e2e` and `cli_e2e` then passed on the release build.
  - `tpm` skips on the build machine (its TPM holds a real device's keys), and `fido_usb` was skipped (no key plugged in).
- The app: `flutter analyze` finds no issues; `flutter test` passes (132 tests), including the LastPass sign-in, the 1Password CLI reader with a fake `op`, and the Credential Exchange page.
- Not tried: Android's Credential Exchange with a real exporting app on a phone (the Kotlin call builds against the library, and the CXF reading is tested), LastPass's real servers, and 1Password's real `op`.
