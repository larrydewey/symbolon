## What's new

### Breach check against Pwned Passwords (SPEC 26.1)

`symbolon device vault breach DIR [--share ID]` checks every login's current password against [Pwned Passwords](https://haveibeenpwned.com/Passwords). The PIN is read from standard input.

- Only the first five hex digits of each password's SHA-1 leave the device. The agent sends one query per distinct prefix, with `Add-Padding: true` so the size of the answer does not reveal the prefix.
- The answer is compared against the password's hash in constant time, and only the count is made public. The agent prints `breached NAME-HEX COUNT` for each breached login, then `checked N breached M`.
- If the service cannot be reached or its certificate does not verify, the check fails. It never reports logins as clean in that case. An item that does not open also fails the check, so a damaged item cannot drop out of the count without anyone noticing.
- Protected items (below) are skipped, and the check prints `protected N not checked`.
- `SYMBOLON_BREACH_URL` and `SYMBOLON_BREACH_CA` name a mirror and its trust anchors. By default the agent trusts `/etc/ssl/certs/ca-certificates.crt`.

### Protected vault items: the cryptographic core (SPEC 18.10)

SPEC 18.10 specifies a second tier of vault items. Opening one needs a threshold OPRF evaluation from the quorum, so one unlocked device cannot open them all. This release contains the core of that design, tested against RFC vectors:

- RFC 9380 hash-to-curve (P256_XMD:SHA-256_SSWU_RO_) and the RFC 9497 VOPRF (P256-SHA256), with batched DLEQ proofs, Feldman verification keys and threshold combination.
- The protected item format: listing fields open with the vault key alone, and the rest need the item's protected key. It covers protect, unprotect and re-key, and such items are never in the duress subset.

Key generation, the cosigner's evaluation endpoint, the agent commands and the app are not built yet, so you cannot protect an item in this release.

### Also

- Changes made after review, before release: the breach check no longer skips items it cannot open, it reports how many protected items it skipped, and the protected item key is refused when the OPRF output is missing or has the wrong length.

## Updating

Install the APK over 0.6.x. It is signed with the same key as before. On Linux, replace the binary. The browser extension is unchanged apart from its version number. Built with [Resid v0.10.1](https://github.com/larrydewey/Resid/releases/tag/v0.10.1).

## Files

- `symbolon-v0.7.0.apk`: the Android app (arm64 and x86_64).
- `symbolon-v0.7.0-linux-x86_64`, `symbolon-v0.7.0-linux-aarch64`: the agent and servers for Linux.
- `symbolon-extension-v0.7.0.zip`: the browser extension.
- `SHA256SUMS`: checksums of the files above.

## Tests

- `symbolon-resid/tests/run.sh`: all 27 unit test files pass, including the new `toprf_ref_test` (RFC 9380 and RFC 9497 vectors, checked against an independent Python implementation), `toprf_test` and `breach_test`. The end-to-end suites pass too: net services, cli (plain and TLS), tpm, home, share, org, store, rotate, breach, fill_lock, browser, ssh, fido and link. `fido_usb` was skipped because it needs a key plugged in.
- `tests/breach_e2e.sh` runs the breach check over HTTPS against a local range service. Two breached logins are reported with their counts, the clean one is not, only padded 5-digit prefixes reach the service, and an untrusted certificate fails the check.
- Not tested: the breach check against the real api.pwnedpasswords.com, or a vault holding protected items (they cannot be made yet). The app itself is unchanged apart from the agent it carries, so the Flutter suite was not run again, and the APK was not tried on a device.
